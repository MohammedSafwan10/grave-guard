# Design: Core Game Loop

## Overview
A pure, deterministic simulation drives everything. The browser layer turns player input into commands,
feeds them to the sim at fixed ticks, and draws the resulting state with Three.js and DOM.

```
 input (mouse/touch/keys)
        │ commands
        ▼
 ┌──────────────┐  events   ┌───────────┐
 │  sim (pure)  │──────────▶│ render    │ Three.js scene, sprites, effects
 │  state+tick  │──────────▶│ ui        │ HUD, spellbook, shop
 │              │──────────▶│ audio     │ SFX + music
 └──────▲───────┘           └───────────┘
        │ answer results
 ┌──────┴───────┐
 │ quiz (pure)  │ picks questions, checks answers, tracks streak
 └──────────────┘
```

## Game loop (`src/app/loop.ts`)
- `requestAnimationFrame` measures real time; an accumulator runs `sim.tick()` at 60 Hz (max 5 ticks per frame
  to avoid a spiral after tab switches).
- Render interpolates between the previous and current state with `alpha = accumulator / dt` for smooth motion.
- Commands are queued with the tick they apply on, which makes replays exact.

## Simulation (`src/sim`)
### State
```ts
interface SimState {
  tick: number;
  rng: RngState;                    // mulberry32 seed
  energy: number;
  lives: number;
  streak: number;
  bellUnlocked: boolean;
  hasteUntil: number;               // tick
  wave: { index: number; status: 'breather' | 'spawning' | 'clearing'; nextSpawnTick: number; queue: Spawn[] };
  defenders: Defender[];            // max 1 per (lane,col)
  enemies: Enemy[];
  bolts: Bolt[];
  runes: Rune[];
  stats: { correct: number; wrong: number; skipped: number; missed: QuestionId[] };
  result: 'playing' | 'won' | 'lost';
}
interface Defender { id: number; kind: DefenderKind; lane: number; col: number; hp: number; cooldown: number }
interface Enemy    { id: number; kind: EnemyKind; lane: number; x: number; hp: number; shield: boolean;
                     slowUntil: number; biting: number | null; shieldReturnTick: number }
```
- Positions are in tiles; `x` is continuous (8.9 → below 0 = gate).
- IDs come from a counter in state, never from time.

### Commands
`placeDefender(kind, lane, col)`, `removeDefender(lane, col)`, `answer(result: AnswerResult)`, `skip()`, `pause()`, `resume()`.
`AnswerResult = { correct: boolean; fast: boolean; boss: boolean; questionId }` comes from the quiz module,
so the sim never needs question content.

### Tick order (fixed, documented, tested)
1. Apply queued commands for this tick.
2. Wave director: spawn due enemies, advance wave status.
3. Defenders: gargoyle fire, bell pulse, rune expiry.
4. Bolts move; resolve hits (armour, shield).
5. Enemies: compute speed (base × haste × slow × calm), detect blocker, bite or move.
6. Gate check, deaths, cleanup.
7. Win/lose check.
8. Emit events collected during the tick.

### Events
`energyChanged, defenderPlaced, placementRejected, defenderDestroyed, boltFired, enemyHit, enemyKilled,
enemySpawned, gateBreached, shieldBroken, shieldRestored, hasteStarted, bellRang, streakChanged,
bellUnlocked, waveStarted, waveCleared, levelEnded`.

## Data (`src/data`)
- `defenders.json`, `enemies.json`: numbers from the balance steering doc.
- `levels.json`: `{ id, name, waves: [{ spawns: [{ atSec, lane, kind }] }] }`. Hand-authored for level 1;
  levels 2–3 can be generated by `tools/gen_waves.ts` from the wave budget rule, then hand-tuned.
- All JSON is validated on load with a small schema helper (zod).

## Quiz hook (`src/quiz`)
- `QuestionPack = { id, title, questions: Question[] }`,
  `Question = { id, topic, difficulty: 1|2|3, prompt, choices: [string,string,string,string], answer: 0|1|2|3, explain }`.
- `createQuiz(pack, seed)` returns `next(): Question`, `submit(id, choice, msTaken): AnswerResult`.
- Picking: no repeats among the last 10; topics with more mistakes are weighted ×2 (adaptive revision).
- Boss questions use difficulty 3 when available.
- The full spellbook UX, packs and the adaptive model get their own spec; this spec ships one built-in pack (times tables).

## Render (`src/render`)
- `Scene`: orthographic-feel perspective camera (fov 35°), fog, moon directional light, point lights per lantern.
- Background: `bg_sky` and `bg_far_hills` on large planes far behind the board; `fg_gate_left` in front at the left.
- Board: 45 tile meshes sharing one material (`tex_tile_stone`), grass strips between lanes (`tex_grass`).
- `SpriteUnit`: textured plane facing the camera, scale from manifest `aspect`, origin from `anchor`, a blurred circle
  shadow mesh, and a tiny shader for hit flash and tint. One `SpriteUnit` per entity, pooled.
- Idle motion: defenders breathe (scaleY ±2%, 0.8 Hz); floating enemies bob (±0.08 tile, 1.2 Hz) and lean;
  Bone Knight step-bob in sync with footstep sounds.
- Bolts: instanced sprites using `vfx_soul_bolt`.
- Picking: raycast pointer to the board plane → (lane, col).
- Post-processing (bloom, vignette) is added in the scene-and-vfx spec; this spec keeps a hook for it.

## UI (`src/ui`)
- `hud.ts` top plaques (wave, energy with gem icon, hearts). `shop.ts` 5 cards. `spellbook.ts` question + 4 buttons + skip.
- Plain DOM components with `mount(root)`, `update(viewModel)`. Text via `textContent` only.
- Layout with CSS grid; the canvas fills the window behind the overlay; spellbook collapses below 900 px width.

## Audio (`src/audio`)
- One `AudioContext`, unlocked on first click. Buffers decoded from `audio-manifest.json`.
- SFX pick a random variant (`_1`, `_2`…) and ±5% pitch so repeats don't sound robotic.
- Music bus with loop (`music_battle`), crossfade to `music_boss` on the Lich wave. Separate music/SFX volume.

## Error handling
- Asset load failure: show a styled retry screen naming the missing file; never a blank canvas.
- Invalid command (e.g. bad tile): rejected with an event, never throws.
- JSON/schema failure in dev: throw loudly with the path; in production: fall back to the built-in pack.
- Tab hidden: auto-pause.

## Testing strategy
- **Unit (Vitest):** each tick step in isolation (placement rules, bite, armour, shield, haste, bell, runes, refund).
- **Property-based (fast-check):** generate random seeds and random timed command lists, run 3–6 minutes of ticks, and check:
  - P1 energy ≥ 0 at every tick, and every change matches an event with a cause;
  - P2 determinism: running twice gives deep-equal states;
  - P3 at most one defender per tile at every tick;
  - P4 no entity with hp ≤ 0 survives the end of a tick;
  - P5 lives only decrease via `gateBreached`, and the level ends exactly when lives = 0 or the last wave clears.
- **Balance bot:** a scripted player (answers 70% right, places gargoyles/lanterns by a simple rule) must win every level of
  the MVP; a 40% bot should usually lose. Run in CI as a test.
- **Playwright:** load the game, start level 1, answer 3 questions, place a gargoyle, take a screenshot, check no console errors.
